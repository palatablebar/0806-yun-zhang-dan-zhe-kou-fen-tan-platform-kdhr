# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。

## 关账与结转

1. 对已核对数据先执行并签发批次（APPROVED 即关账）。关账报告与逐户依据随即冻结。
2. 在批次复核区点击「结转下月」，工作台按 `账户额度 − 已签发分摊` 生成下月可签发批次与逐户结转依据。重复点击只返回同一条。
3. 来源未齐时可上传补录 CSV（「补录来源」）。补录只并入尚未签发的下月批次，已关账账期保持原样；纯重复回放会标记「待补来源」。
4. 出现超额或额度缺失时批次为阻断态，状态区列出记录键。先补齐来源解除阻断，再签发；阻断态无法签发，且失败不改变批次。
5. 点击「签发下月批次」整批原子生效；已签发批次不能再补录或重复签发。
6. 通过「下载结转证据」保存逐户依据、阻断键与 CREATED/SUPPLEMENT/ISSUED 事件链。

财务可先按已核对数据关账，再等来源齐全通过补录修正下月批次，避免结转偏大；折扣池或账户额度始终缺失时批次保持阻断，不会签发。
